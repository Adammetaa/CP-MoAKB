# Concept Authoring

A Concept Candidate may emerge only when reviewed Claims and existing identity
governance support a distinguishable, stable meaning requiring its own identity.
It states definition, category, scope, exclusions, distinctions, ambiguity, and
disambiguation while referencing supporting Claims and Evidence.

Concepts must never be invented from terminology alone, capitalization, repeated
words, headings, filenames, translation, UI needs, or Package layout. A Claim does
not automatically require a new Concept, and a Concept is not a collection of copied Claims.

Concept acceptance requires separate competent ontology, domain, terminology,
Evidence, and governance review under the existing Object Model.
