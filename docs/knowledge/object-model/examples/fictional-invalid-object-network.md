# Fictional Invalid Object Network

Status: Illustrative anti-pattern

## Purpose

Demonstrate boundary violations that MUST be rejected before acceptance.

## Invalid Network

1. Two copied objects both claim to be fictional Concept **Umbra**, but use
   unrelated identities. This duplicates Concept identity.
2. An Evidence item contains the complete proposition and is treated as the
   Claim. This collapses Evidence and Claim.
3. The label “Umbra” is used as Concept identity. This makes a Term the identity.
4. Two cards appear next to one another, and the interface treats adjacency as a
   Relationship. No Relationship Object exists.
5. Decision **D-Skip** claims acceptance without a Review, fixed input version,
   Findings, competence, or dissent record.
6. A public page is called published without authorization or a Publication
   Record.
7. A translated card is assigned a new Knowledge identity merely because it is a
   Representation.
8. Package membership points to “latest Umbra,” a floating ambiguous version.

## Required Disposition

The network MUST remain blocked. Editors MUST preserve the defects as Findings
or Unresolved Issues, restore distinct identities and exact references, create
the missing governed objects, and repeat competent review. A UI, validator,
majority vote, or repository commit MUST NOT infer or manufacture the missing
meaning or authority.

## Non-remedy

Renaming files, combining cards, assigning a score, selecting the newest object,
or publishing a correction without prior authorization does not repair the
network. This example authorizes no actual corrective workflow.
