# Canonical Knowledge Authoring Templates

Status: Active
Version: 1.0

## Purpose
Provide one discoverable family of human authoring, review, lifecycle, and package templates.
## Scope
Implementation-neutral preparation for future governed knowledge work.
## Out of Scope
This family MUST NOT create schemas, executable forms, records, datasets, Runtime behavior, or publication.
## Authority
The [Template Governance](template-governance.md) document and all higher
knowledge authorities govern this family.
## When to Use
Use only for authorized human editorial preparation before any physical representation is approved.
## Who Completes It
Authors, reviewers, editors, governance roles, and release roles complete only their assigned templates.
## Required Inputs
Applicable authority versions, approved scope, candidate identities where available, and accountable roles.
## Template Fields

- [Authoring templates](authoring/source-nomination-template.md)
- [Review templates](review/review-finding-template.md)
- [Lifecycle templates](lifecycle/correction-template.md)
- [Package templates](packages/source-evidence-package-template.md)
- [Fictional examples](examples/README.md)

## Completion Rules
Every field MUST be completed, marked with an explicit permitted absence state, or omitted only when optional.
## Prohibited Content
Machine data types, syntax rules, schemas, real agricultural content, diagnosis, recommendation, inference, and scores.
## Review Requirements
Completion requires the reviews named by each template and MUST NOT imply acceptance.
## Failure Modes
Treating labels as machine keys, blanks as unknown, or a completed package as authority.
## Example
A fictional source package MAY use the templates while remaining unaccepted and unpublished.
## Non-example
A YAML document copied from these headings MUST NOT be treated as a universal format.
## Audit and Retention
Retain template version, completed version, accountable roles, reviews, changes, and disposition.
## Change Control
Family changes require authority, documentation, and verifier review.
