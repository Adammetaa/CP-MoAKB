# Knowledge Author Checklist

Status: Active
Version: 1.0

## Purpose
Verify an author package before specialist review.
## Scope
Identity, definition, scope, evidence, terms, relationships, rights, and history.
## Out of Scope
Completion MUST NOT grant acceptance or publication.
## Authority
Use under the [handbook](../knowledge-editorial-handbook.md) and KAS-001 through KAS-007.
## Definitions
**RR** means revision required; **N/A** requires a reason.
## Responsibilities
The Author completes every row; Domain Editor checks completeness.
## Procedure
Mark one result per row and add notes/evidence. Any Fail or RR blocks handoff.
## Required Inputs
Candidate package and applicable authorities.
## Required Outputs
Completed instrument and revision list.
## Review Points
| Review item | Pass | Fail | N/A | RR | Reviewer notes |
| --- | --- | --- | --- | --- | --- |
| Identity is label-independent and class is declared | [ ] | [ ] | [ ] | [ ] | |
| Definition, scope, exclusions, and uncertainty are explicit | [ ] | [ ] | [ ] | [ ] | |
| Every claim has evidence and locator traceability | [ ] | [ ] | [ ] | [ ] | |
| Terms and relationships are separately nominated | [ ] | [ ] | [ ] | [ ] | |
| Rights, conflicts, lifecycle, and history are recorded | [ ] | [ ] | [ ] | [ ] | |
## Failure Modes
Blank rows, unjustified N/A, missing links, or self-approval.
## Examples
An RR row cites the missing evidence item.
## Non-examples
“Looks good” without row findings MUST NOT pass.
## Escalation
Send specialist questions to the competent reviewer.
## Audit Requirements
Retain the completed checklist, notes, role, and revision closure.
## Change Control
Checklist meaning changes require handbook governance review.
## Future Considerations
This remains a document, not a software form.
