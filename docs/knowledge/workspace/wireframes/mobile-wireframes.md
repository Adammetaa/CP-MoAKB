# Mobile Wireframes

**Status:** Static design blueprint
**Version:** 0.1.0

## Layout Principle

Mobile layouts use a single linear column. Object identity, fixed version, status, active role, prototype notice, and critical governance warning precede content. Consequential actions remain visible after their decision context, not in gesture-only menus.

## Dashboard

```text
[Knowledge Lab — future]
[Role: Author] [Menu]
[Prototype notice]
My Tasks
- type / object / authority
  human priority / expected action
Queues
- Drafts - Review - Revision
Recent governed activity
```

“No assigned tasks are recorded” is the neutral empty state.

## Source Candidate

```text
[SC-FICTION-001] [Draft] [v2]
Source identity and type
Authority classification
Citation and access details
Nomination rationale
COI declaration
[Governance warnings]
[Save draft]
[Submit for review]
```

Missing required human-supplied details block submission; no automatic source classification occurs.

## Evidence Item

```text
[EV-FICTION-001] [v1]
Parent source + exact locator
Excerpt / faithful record
Preserved context
Scope and limitations
Provenance chain
Linked claims
[Revise] [Submit evidence review]
```

Unavailable context is an error, never a generated replacement.

## Concept Candidate

```text
[CC-FICTION-001] [author revision] [v3]
Identity proposal
Terminology / ontology authority references
Scoped human-authored claim
Evidence links and conflicts
Open findings
[Compare v2 and v3]
[Respond] [Resubmit]
```

No label, relationship, or claim is inferred.

## Review Detail

```text
[RV-FICTION-001] [assigned]
Fixed review target: CC-… v3
Competence declaration
COI clearance
Candidate and evidence context
Checklist
[Add finding]
[Return review]
```

A stale target or uncleared conflict visibly blocks completion.

## Finding Resolution

```text
[F-01] [major scope issue] [open]
Reviewer statement + references
Author response + revision
Reviewer verification
[Keep open] [Resolve] [Escalate]
Preserved discussion and history
```

Silence never resolves a finding; disagreement remains available to assistive technology and governance review.

## Acceptance Gate

```text
[Acceptance gate]
Candidate fixed version 4
Review completion
Finding disposition
Evidence traceability
Authority / COI / exceptions
Decision rationale
[Accept] [Reject] [Return]
Acceptance is not publication.
```

Unresolved blockers are named before unavailable actions.

## Accessibility, Governance, and Change Control

The future design requires reflow without horizontal scrolling, minimum touch targets, visible focus, descriptive controls, heading structure, and live-error announcements. Thai-first labels must remain concise while governed English terms stay discoverable. Consequential actions require KGS authority and audit records. This is not an app or implementation authorization.
