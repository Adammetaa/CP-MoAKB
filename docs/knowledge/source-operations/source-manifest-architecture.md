# Conceptual Source Manifest

Status: Active

Version: 1.0

Every governed Source has one conceptual manifest associated with one exact
Source identity/version. The manifest makes operational governance reviewable; it
is not the Source, Evidence, Knowledge, or a production record format.

The manifest conceptually identifies Source Identity, title, publisher,
institutional/personal author where applicable, authority and scope, document
type, exact version/edition/revision, publication/effective date, language,
jurisdiction, rights dispositions, lifecycle/availability status, descriptive
coverage, retrieval/acquisition provenance, access/custody, integrity metadata,
correction/retraction/replacement state, supersession references, review status,
limitations, and audit references.

It defines no JSON, YAML, XML, keys, field types, cardinality, syntax, schema,
API, table, storage, checksum algorithm mandate, or validator. A conceptual
responsibility may be unknown only when explicitly recorded and governed as a blocker.
