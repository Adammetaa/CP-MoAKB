# Conceptual Package Manifest Model

Status: Active

Version: 1.0

## Definition

The Manifest is a conceptual governance inventory, not a production schema. It
identifies what reviewers and consumers must be able to determine without
choosing physical fields, types, syntax, order, or serialization.

## Conceptual Responsibilities

The Manifest identifies Package identity; title/label references; purpose; scope;
Package profile; Package Version; lifecycle and publication states; Package
authority; owner/custodian; exact members; dependency Packages; applicable domain
and crop; language coverage; Evidence coverage; unresolved blockers; Review State;
rights state; consumer eligibility; superseded Package Version; provenance; and
audit references.

## Prohibitions

It defines no JSON/YAML schema, required key spelling, cardinality, identifier
syntax, database column, API payload, validation algorithm, or Runtime contract.
Implementations require separate Design Freeze and architecture approval.
