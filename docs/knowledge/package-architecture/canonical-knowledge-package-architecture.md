# Canonical Knowledge Package Architecture

Status: Active

Version: 1.0

## Purpose and Ownership

A CKP exists so Website, SPA Assistant, Investigation Engine, Human Review, and
future AI contexts can reuse one governed knowledge basis. It owns Package
identity, purpose, scope, exact membership decisions, dependency declarations,
composition review, lifecycle, and Package Version history.

It references rather than owns canonical Concepts, Claims, Terminology,
Relationships, Observations, Sources, Evidence, Authorities, Reviews, Decisions,
Unresolved Issues, lifecycle events, publication records, and representations.
It does not own consumer UI copy, Case content, inference, or recommendations.

## Canonical Flow

> Scientific / Official Sources -> Source Objects -> Evidence Objects -> Claim /
> Concept / Relationship Objects -> Canonical Knowledge Assets -> CKP ->
> Governed Views

Every membership binds an exact governed version. The Package MUST NOT become one
giant duplicated record and MUST NOT bypass Evidence or Source provenance.

## Lifecycle and Publication

Package lifecycle records proposal, review, acceptance, revision, deprecation,
supersession, retirement, and archive of the composition. It does not change a
member's lifecycle. Package acceptance is not publication. Publication requires a
separate exact-version authorization and does not publish ineligible members.

## Consumer Reliance

A consumer may rely on exact membership, declared scope, dependency compatibility,
review/publication state, authority, rights, provenance, limitations, and consumer
eligibility for the stated version. It may not infer truth, applicability,
Diagnosis, Recommendation, or completeness from membership.

## Scientific Separations

Observation, Evidence, Knowledge, Hypothesis, Diagnosis, Recommendation, Decision,
Action, and Outcome remain separate. Active Ingredient and Mode of Action do not
equal Recommendation; registration does not equal Recommendation; Package does
not equal Case Record.
