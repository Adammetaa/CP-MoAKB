# Package Boundary

Status: Active

Version: 1.0

## Conceptual Package Content

A CKP may declare Package identity, purpose, scope, exact Asset memberships,
exact Object references, applicable terminology and Relationships, Evidence
coverage summary, unresolved issues, review/lifecycle/publication states,
consumer eligibility, provenance, rights status, and version dependencies.

## Reference, Do Not Duplicate

A CKP MUST NOT embed copied full Source text, copied Evidence owned elsewhere,
UI prose treated as Knowledge, hard-coded Website layout, ChatGPT answers, model
output as accepted Knowledge, Case Diagnosis or Recommendation, confidential Case
content, proprietary product preference, or hidden inference results.

Source is not Package. Evidence is not Package. Package Membership selects exact
governed versions and creates neither ownership transfer nor scientific meaning.

## Identity Boundary

Package identity is separate from Concept, Claim, Source, Evidence,
Representation, Website URL, file path, display title, and language-label identity.
Renaming or moving a representation cannot silently create a Package version.

## Implementation Boundary

This architecture chooses no YAML/JSON shape, field type, class, table, API,
parser, registry, validator, resolver, storage engine, or Runtime behavior.
