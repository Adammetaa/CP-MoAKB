# Knowledge and Investigation Integration

Status: Active

Version: 1.0

## Integration Principle

The MVP consumes governed architecture and objects through explicit,
version-aware, purpose-bound references. Knowledge is never silently retrieved,
applied, or allowed to override case evidence. This document defines conceptual
use, not APIs, storage, retrieval, or runtime dependency.

## Architecture Consumption

- Observation Architecture governs direct capture meaning and provenance.
- Observation Vocabulary supplies reviewed neutral terminology without diagnosis.
- Investigation Ontology governs states, gaps, needs, candidates, differentials,
  findings, and review boundaries.
- Investigation Question Bank governs reusable patterns; SPAs select and adapt
  Question Instances manually.
- Investigation Blueprint governs readiness, stages, evidence collection,
  visibility, escalation, and Management Options eligibility.

## Object Responsibilities

| Object or record | MVP use and boundary |
|---|---|
| Knowledge Object | governed content identity and lifecycle; never hidden case reasoning |
| Source Object | exact origin and custody; source presence is not Evidence |
| Evidence Object | reviewed relevance to a precise use; separate from Evidence Need and material quality |
| Claim Object | governed proposition outside automatic Finding promotion |
| Concept Object | stable governed meaning; not case truth |
| Terminology Object | labels and language relationships; local term does not confirm identity |
| Review Object | accountable review scope, rationale, outcome, and conflict |
| Finding Object | separately governed finding responsibility; Investigation Finding does not become it automatically |
| Decision Object | attributable user choice separate from option and Action |
| Action and Outcome records | what occurred and what was later captured, without causal inference |
| future Product Knowledge | reviewed product, label, registration, safety, and limitation facts under separate authority; never recommendation logic |

## Knowledge-use States

Every consulted reference is explicitly classified for the bounded case as:

- **consulted:** examined, without asserting applicability;
- **applicable:** human-reviewed as relevant to the stated context;
- **not applicable:** reviewed as outside the bounded context, with rationale;
- **challenged:** authority, meaning, relevance, or interpretation is disputed;
- **outdated:** supersession or currency concern is explicitly identified;
- **awaiting review:** use is pending qualified human assessment; or
- **used in rationale:** exact contribution to a candidate, criterion, finding,
  or eligibility explanation is disclosed.

These states are not automatic, mutually inferred, or global judgments about the source.

## Dependency Rules

Knowledge consultation follows evidence-needs organization and informs, but does
not generate, Hypothesis Candidates. Product Knowledge cannot override scientific
evidence, label limitations, regulatory review, or human authority. Outcome does
not revise the knowledge used historically. A new insight becomes a Learning
Candidate and follows Knowledge Review before any Approved Knowledge Package.

## Learning Loop

> Field -> SPA -> Investigation -> Agronomist Review -> Reviewed Finding ->
> Outcome -> Learning Candidate -> Knowledge Review -> Approved Knowledge Package

Nominable candidates include a new observation pattern, terminology, missing
question pattern, missing Evidence Need, unusual hypothesis, repeated unresolved
case, conflicting knowledge, treatment outcome, workflow friction, or field
usability issue. Nomination never creates Knowledge or publication eligibility.
