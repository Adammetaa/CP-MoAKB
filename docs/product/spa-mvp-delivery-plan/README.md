# SPA MVP Delivery and Field Validation Plan

Status: Active

Version: 1.0

## Purpose

This family converts the approved [SPA MVP Definition](../spa-mvp-definition/README.md)
into three bounded delivery increments and a governed Field Validation Plan. It
seeks the shortest safe path to operational SPA value without weakening
scientific, evidence, review, privacy, or governance boundaries.

## Increment Sequence

1. **Increment A — SPA Investigation Capture:** turn an incomplete report into a
   structured, traceable package ready for review.
2. **Increment B — Human Review and Differential Investigation:** preserve and
   compare provisional explanations and record a reviewed or unresolved finding.
3. **Increment C — Follow-up, Outcome, and Learning Candidate:** preserve what
   was decided, done, and later observed, then nominate learning for review.

A conceptual module is not one screen, service, application, deployment unit,
database, or technical component. Increments group user value and governed
dependencies, not document or implementation structure.

## Permanent Separation

Reported Information is not Direct Observation. Observation is not Evidence.
Information Gap is not Negative Observation. Question Pattern is not Question
Instance. Evidence Need is not Evidence Object. Hypothesis Candidate is not
Diagnosis. Differential Comparison is not automatic ranking. Investigation
Finding is not Recommendation. Management Option is not Decision. Decision is
not Action. Action is not Outcome. Learning Candidate is not Approved Knowledge.

## Out of Scope

This plan defines no software, implementation backlog, estimate, Runtime,
infrastructure, schema, API, database, synchronization mechanism, permission
system, UI, wireframe, dataset, diagnosis, recommendation, scoring, ranking, AI,
release, or publication artifact.
