# Dependency and Readiness Map

Status: Active

Version: 1.0

## Readiness Categories

| Category | Increment A | Increment B | Increment C |
|---|---|---|---|
| Architecture | approved Investigation Blueprint and SPA MVP Definition; intake/capture boundaries | A package contract and differential/review boundaries | Decision, Action, Outcome, closure, and learning boundaries |
| Knowledge | approved Observation terminology and Question Pattern subsets; Evidence capture rules | governed crop-investigation Vertical Slice; minimum candidate/criteria/evidence content | governed Outcome terminology and Learning Candidate categories |
| Governance | privacy/location/consent; provenance; pilot authority | reviewer matrix, disagreement, escalation, review record | no-promotion rule, learning review, sensitive outcome handling |
| Product | manual case capture, incomplete save/resume, summary and review preparation definition | review request/return/handoff and finding definition | reviewed-output presentation, follow-up, outcome, reopening, nomination definition |
| Human capability | identified/trained SPA participants and support | confirmed qualified reviewers with capacity and authority | assigned follow-up owners and Knowledge Review capacity |
| Field operations | safe channels, evidence package, field intake preparation | review handoff usable during field/remote operations | practical follow-up access and seasonal opportunity |
| Validation | Round 0 materials, case sample, success/failure/stop/debrief instruments | validated A cases and Round 2 observer plan | validated B findings and Round 3/4 continuity plan |

Readiness is not claimed where an item is absent. Conditional readiness records
the gap, owner, affected activity, and decision to pause or narrow scope.

## Critical Path

> Sprint-048P Delivery and Validation Plan -> Rice Knowledge Vertical Slice ->
> Human Review Operating Model -> Increment A Product Definition -> Increment A
> Implementation -> Field Validation Round 1 -> Increment B Product Definition
> -> Increment B Implementation -> Field Validation Round 2 -> Increment C
> Product Definition -> Increment C Implementation -> SPA MVP Pilot Completion

Round 0 occurs before field validation. Round 3 validates C continuity, and Round
4 integrates all approved increments before pilot completion. This is a planning
sequence, not implementation authorization.

## Parallel Streams

| Stream | Why parallel / must not assume | Handoff and block | Owner role and completion evidence |
|---|---|---|---|
| Rice Vertical Slice | content governance can begin before product build; must not assume UI or diagnosis | approved scoped package; blocked by sources/review | Knowledge lead; reviewed authority/provenance package |
| SPA Field Intake Template | operational semantics can be tested; must not become schema/form | reviewed intake language to A; blocked by Blueprint | Product/SPA lead; walkthrough evidence |
| Reviewer Role Matrix | authority design is independent; must not assume technical permissions | operating model to B; blocked by named authority decisions | Review/Governance lead; approved matrix and escalation rules |
| Privacy and location governance | cross-cutting policy can precede cases; must not assume storage | handling rules to all increments; blocked by legal/governance authority | Governance/Privacy role; approved controls |
| Field Evidence Package | capture guidance can be prepared; must not claim Evidence acceptance | governed subset to A/B; blocked by evidence standards | SPA/Agronomist; reviewed package |
| Case sampling preparation | recruitment and case diversity planning can start; must not preselect easy success | sample proposal to validation; blocked by crop scope/consent | Validation lead; approved sampling frame |
| pilot recruitment | availability can be established early; must not start validation | participant roster and consent; blocked by Owner approval/training | SPA Operations; readiness confirmation |
| training materials | boundary education can follow approved definitions; must not teach unapproved behavior | trained-role evidence; blocked by stable scope/content | Training/Review lead; observed walkthrough |
| measurement-plan design | evidence definitions can precede pilot; must not set final targets or optimize speed only | collection plan; blocked by success model/privacy | Validation analyst; reviewed measures |
| report contract design | conceptual output semantics can be aligned; must not design layout/API | reviewed output responsibilities; blocked by explainability model | Product/Review lead; traceability walkthrough |

Parallel work cannot declare the downstream gate ready before required handoffs are approved.
