# Website Knowledge View Model

Status: Active

Version: 1.0

## Interpretation

Views are conceptual presentation abstractions, not pages, routes, components,
schemas, API responses, database projections, or Runtime models. A view composes
eligible representations without owning canonical meaning.

| View | Purpose and eligible content | Required explanation | Exclusions |
|---|---|---|---|
| Concept View | explain an exact Concept version, definition, scope, terminology, sources, relationships, review, packages | canonical reference/version, authority, status, provenance, limitations | no inferred identity, applicability, Diagnosis, or recommendation |
| Investigation View | explain governed investigation roles and flow, with eligible examples | layer distinctions, authorship, evidence/review boundary, unresolved meaning | no active case, automated progression, candidate selection |
| Observation View | explain or present eligible bounded Observation representation | observer/source, method, context, result, uncertainty, provenance | no Evidence promotion, cause, Claim, or Diagnosis |
| Source View | explain exact Source version, authority context, citation, custody, rights, related explicit uses | source identity/version, retrieval/custody, limitations, relationship roles | no credibility score or automatic Evidence relevance |
| Relationship View | present one or more exact asserted relationships | source/target/type/direction/basis/scope/review/version | no inferred edge, composition, hidden rank |
| Explainability View | reconstruct canonical object, provenance, sources, relationships, reviews, versions, limits | why shown, origin, authority, changes, omissions, non-implications | no generated conclusion or case advice |
| Package View | explain eligible Knowledge Package scope, membership, versions, authority, lifecycle, limitations | package version, exact included representations, status and dependencies | no assumption every referenced item is public or applicable |

## Cross-view Consistency

The same canonical version has consistent meaning across views. Audience,
language, purpose, and permitted omissions may differ, but material differences
are declared. Views link through exact canonical or editorial-navigation
relationships with their type visible.

## View State

Loading, empty, restricted, unavailable, deprecated, superseded, pending, and
not-published meanings are product presentation concerns only. They never update
the canonical object or substitute for its lifecycle state.

## Future Extension

Future SPA or reviewer views may add role-bounded case context only under
separate governance. They must reuse canonical references and cannot fork
scientific meaning from public Website views.
