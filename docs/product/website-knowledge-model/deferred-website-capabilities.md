# Deferred Website Capabilities

Status: Active

Version: 1.0

## Deferral Principle

Deferred capabilities are outside Website Alpha and this Knowledge Model. Their
mention defines a boundary and prerequisite, not approval or roadmap commitment.

| Capability | Why deferred | Minimum future prerequisites |
|---|---|---|
| AI | no authorized advisory model or evaluation exists | governed purpose, data, evaluation, explanation, uncertainty, Human Review, safety and release authority |
| Image Intelligence | representations must not classify images | authorized corpus, consent/rights, neutral labels, performance/bias evidence, human confirmation |
| Diagnosis | outside Website and canonical presentation authority | separate diagnostic governance, qualified evidence, scientific validation, Human Review and safety |
| Recommendation | no recommendation authority or Product Knowledge operation | reviewed investigation, regulatory/safety/product governance, explanation and human Decision separation |
| Product Selection | would risk commercial/scientific boundary collapse | governed Product Knowledge, label/registration review, neutrality, authority and no-sales-optimization controls |
| Active Investigation | Alpha is read-only knowledge presentation | SPA MVP Increment A, case/privacy/provenance architecture, field validation and implementation approval |
| Human Review Workspace | Website does not operate reviews | Human Review Operating Model, reviewer qualifications/authority, sensitive visibility, audit and validation |
| SPA Workspace | future persona path is non-functional | SPA MVP definitions/increments, crop Vertical Slice, roles, offline/field, implementation and pilot approval |
| Enterprise Administration | Program Administrator is not a superuser | organization/identity/privacy/audit governance, validated production and authority separation |
| Analytics | metrics could create hidden ranking or privacy risk | approved measures, aggregation, consent, provenance, bias, access, explanation and governance |

## Permanently Preserved Constraints

No future capability may create a second Knowledge Base, silently alter
canonical meaning, infer ungoverned relationships, hide provenance/status,
collapse epistemic layers, or self-learn from unreviewed cases. Future AI remains
advisory and Human-reviewed if separately authorized.

## Authorization Path

Future work requires Product Definition, Architecture Review, applicable
Knowledge/Scientific/Privacy/Regulatory/Human Review readiness, implementation
authorization, validation, Release eligibility, and Publication approval where public.
