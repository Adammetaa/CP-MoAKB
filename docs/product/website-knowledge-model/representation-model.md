# Website Representation Model

Status: Active

Version: 1.0

## Representation Principle

Website representations are read-only conceptual projections of exact governed
versions. They express canonical responsibility for a declared audience and
purpose; they never redefine canonical meaning or become separate Knowledge Assets.

| Canonical responsibility | Website presentation responsibility | Prohibited interpretation |
|---|---|---|
| Knowledge Object | show eligible type, meaning, identity reference, version, authority, status, relationships, and limits | Website card/page is the canonical object |
| Concept | show definition, scope, distinctions, labels, related asserted Concepts, and authority | popularity or navigation position changes Concept meaning |
| Terminology | show preferred/alternative labels, language, definition relationship, status, and notes | label equivalence creates Concept identity or scientific confirmation |
| Observation | explain bounded capture, observer/source, context, method, result, uncertainty, and provenance where eligible | Observation proves cause, Claim, Evidence role, or Diagnosis |
| Investigation | explain states, gaps, questions, needs, provisional candidates, comparison, review, and findings | representation executes workflow or chooses an explanation |
| Evidence | show exact Evidence Object’s scoped relevance, Claim/use, limitations, source, review, and version | source presence or quality alone proves content |
| Source | show exact origin, authority context, citation, custody, rights/status, and relevant versions | credible-looking source is automatically applicable Evidence |
| Review | show reviewer authority, purpose, scope, status, rationale, conditions, dissent, and date where eligible | approval is universal truth or publication |
| Finding | show exact bounded finding, basis, category, review, limits, unresolved issues, and lifecycle | Finding automatically becomes Claim, Diagnosis, or Recommendation |
| Relationship | show only exact asserted source, target, type, basis, scope, version, and review | displayed adjacency or graph path creates a relationship |

## Representation Composition

A view may compose several approved representations only when every source
version remains identifiable and incompatible versions are not silently merged.
Omission, summarization, ordering, and transformation are disclosed. Composition
creates no aggregate scientific conclusion.

## Fidelity Review

Review checks canonical source, version, audience, semantic fidelity, omissions,
language, accessibility, rights, security, visibility, and publication
competence. Failure includes unknown source version, mixed versions,
mistranslation, hidden limitation, inferred link, or false publication status.

## Implementation Neutrality

No serialization, view-model class, query, URL, content-management system,
database projection, or rendering mechanism is defined.
