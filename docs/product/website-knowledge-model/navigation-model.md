# Knowledge Navigation Model

Status: Active

Version: 1.0

## Principle

Navigation follows governed knowledge meaning rather than implementation,
repository layout, storage, page hierarchy, or workflow execution. A navigation
path is a presentation aid, not a semantic relationship unless the canonical
relationship is separately asserted.

## Navigation Dimensions

| Dimension | Navigation purpose | Boundary |
|---|---|---|
| Concept | move from eligible Concept representation to definition, terminology, sources, relationships, packages, and review | no equivalence, hierarchy, or causality inferred from links |
| Topic | group eligible representations for orientation under a declared editorial purpose | Topic grouping is not a canonical Concept or taxonomy unless governed as such |
| Investigation | move through explanatory roles such as Observation, gap, question, need, candidate, differential, and review | path does not execute a case or imply automatic progression |
| Relationship | traverse an exact asserted relationship to its source, target, basis, and review | traversal does not compose or infer further links |
| Source | inspect eligible objects that explicitly reference an exact Source version and role | common Source does not make objects equivalent or mutually supporting |
| Review State | discover representations by exact governed review condition | filter does not approve, reject, or rank content |
| Knowledge Package | explore eligible package scope, membership, versions, authority, limitations, and lifecycle | package membership does not imply applicability or publication of every reference |

## Context Preservation

Navigation retains the starting representation, destination type, canonical
reference, relationship basis, version, language, status, and return context.
Cross-language navigation preserves the original expression and alignment review.

## Non-executable Boundary

Breadcrumbs, next links, sequence diagrams, related items, filters, and future
workspace links never trigger questions, evidence acceptance, hypothesis
selection, review, or lifecycle change. “Next” means navigational continuity only.

## Multiple Paths

An object may appear through several topics, packages, relationships, or sources.
Multiple paths do not create multiple canonical identities. The Website exposes
why each path includes the representation and prevents path-specific meaning from
silently overwriting canonical meaning.
