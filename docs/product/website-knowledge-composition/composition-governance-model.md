# Composition Governance Model

Status: Active

Version: 1.0

## Principle

Composition applies existing governance; it never changes governance, grants
authority, approves knowledge, or publishes content.

## Governance Controls

| Control | Composition obligation |
|---|---|
| composition eligibility | confirm approved View, purpose, audience, rights, privacy, security, language, and lifecycle suitability |
| review expectations | review semantic fidelity, omissions, compatibility, explanation, accessibility responsibility, and traceability |
| publication visibility | show only content authorized for the exact publication context; reachability is not publication |
| version compatibility | compose exact compatible canonical and Representation Versions without silent merging |
| supersession | identify replacement and effective context while preserving prior trace |
| deprecation | disclose discouraged use, rationale, limits, and replacement where approved |

## Decision Separation

Knowledge authority owns canonical meaning. Representation governance owns View
fidelity. Publication authority owns public eligibility. Product architecture
owns the conceptual composition purpose. No one composition decision substitutes
for another authority's decision.

## Review Outcome

A composition review may accept, condition, reject, or require revision of the
assembly. It cannot alter a source View or Canonical Object. Source defects are
referred to their owning process and remain visible or block composition as required.

## Change Control

Changes to Page purpose, Section boundaries, View selection, ordering, summaries,
or patterns require proportional composition review. Changes affecting canonical
meaning, governance, publication, or Design Freeze follow their existing separate
change controls.
