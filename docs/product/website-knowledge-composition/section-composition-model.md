# Section Composition Model

Status: Active

Version: 1.0

## Composition Hierarchy

> Page -> Sections -> Knowledge Views -> Canonical Knowledge

A Section is a conceptual, purpose-bounded grouping within a Page. It organizes
eligible Views for comprehension but does not own their meaning or governance.

## Required Section Declaration

| Element | Required declaration |
|---|---|
| purpose | the user understanding the Section supports |
| inclusion boundary | eligible View types, audience, scope, and version conditions |
| exclusion boundary | content, states, or implications that must not appear |
| traceability expectations | identity, provenance, source, and version paths retained |
| explainability expectations | why content is included, related, limited, or unavailable |

## Section Rules

A Section uses approved Knowledge Views only. It cannot extract ungoverned facts
directly from Canonical Objects, join Views into a new conclusion, suppress a
material limitation, or imply a relationship through adjacency. If ordering is
editorial rather than canonical, that distinction remains clear.

## Empty and Restricted Sections

An empty, restricted, ineligible, pending, or unavailable Section must not imply
that canonical knowledge does not exist. Where disclosure is permitted, the Page
explains the presentation condition without leaking protected content.

## Reuse

A Section pattern may recur across Pages, but each use re-evaluates eligibility,
compatibility, audience, publication state, and current version references.
