# Deferred Composition Capabilities

Status: Active

Version: 1.0

## Boundary

The following capabilities are explicitly deferred. Their mention is not a
roadmap commitment, implementation authorization, or publication decision.

| Capability | Why deferred |
|---|---|
| Runtime rendering | composition is conceptual and defines no execution behavior |
| UI framework | no React or other framework architecture is authorized |
| CMS | Website composition is not a CMS content model or repository |
| Editing | composed Pages are read-only presentation concepts |
| Authoring | knowledge and View authoring remain outside composition |
| Dynamic layout | no rules engine, responsive behavior, or live assembly is defined |
| Personalization | audience-specific selection requires separate privacy, bias, explanation, and governance architecture |
| AI composition | no model may generate, select, rank, summarize, or relate knowledge here |
| Automatic page generation | no automation may convert canonical content into public Pages |
| Runtime optimization | caching, indexing, bundling, prefetching, and performance behavior are implementation concerns |

## Future Preconditions

Any future capability requires separate Product Definition, Architecture Review,
applicable Knowledge, Scientific, Privacy, Security, Human Review, and Publication
governance, implementation authorization, validation, and Design Freeze change
control where applicable.

Future work must preserve the Knowledge View/Knowledge Object separation,
deterministic traceability, explainability, exact version identity, visibility,
and the prohibition on inference and authoring through composition.

## Current Effect

No deferred capability exists by implication. This sprint creates documentation
only and introduces no Runtime dependency, executable behavior, UI, CMS, AI,
automation, release, deployment, or publication artifact.
