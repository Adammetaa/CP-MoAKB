# Composition Purpose and Boundary

Status: Active

Version: 1.0

## Purpose

Composition gives information architects a consistent conceptual method for
placing approved Knowledge Views into sections and pages while keeping every
source's meaning and governance visible. It supports reusable, explainable
Website structures without duplicating canonical knowledge.

## Composition Chain

> Canonical Knowledge -> Canonical Knowledge Objects -> approved Knowledge Views
> -> Sections -> Pages

Every step is a presentation relationship. No downstream layer owns or changes
the meaning of an upstream layer.

## Permanent Separations

| Composition concern | Remains separate from |
|---|---|
| Knowledge View selection | Knowledge creation, review, or publication approval |
| Section grouping | canonical classification or Relationship assertion |
| Page organization | Knowledge Object identity or lifecycle |
| presentation component choice | semantic type or scientific authority |
| navigational placement | applicability, ranking, inference, or recommendation |

The model does not define a Knowledge Object Model, Website database, authoring
model, AI knowledge layer, Runtime UI framework, rendering engine, CMS model, or
navigation execution.

## Integrity Obligations

Composition retains exact canonical and representation identities, provenance,
authority scope, Review State, publication state, version identity, limitations,
and traceability. Omission or arrangement must not imply evidence, endorsement,
causality, equivalence, currency, or applicability that canonical knowledge does
not assert.

## Change Boundary

A composition change may alter placement or presentation purpose only. A change
to scientific meaning, relationship, authority, review, publication, or lifecycle
must return to its owning governance process and cannot be made through a page.
