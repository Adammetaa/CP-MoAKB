# Website Page Boundaries

Status: Active

Version: 1.0

## Interpretation

“Page” means a conceptual content responsibility, not a route, screen, layout,
component, template, or React implementation. Several responsibilities may later
share a page, and one responsibility may have several representations.

| Page responsibility | May present | Must not present or perform |
|---|---|---|
| Home | purpose, non-goals, Alpha status, principal destinations | symptom input, advice, production claim, personalization |
| Knowledge landing | eligible families/packages, scope, authority, lifecycle | duplicate master data, unreviewed content, hidden applicability |
| Knowledge object detail | exact representation, source, relationships, version, status, limits | edit canonical object, infer graph relationships, diagnose |
| Investigation overview | governed flow, distinctions, Human Review boundary, examples | active case intake, question automation, candidate generation |
| Observation explanation | neutral capture meaning, context, provenance, uncertainty | causal interpretation or Evidence promotion |
| Evidence/traceability explanation | source, evidence relevance concept, review and limitations | claim that source presence proves content |
| Knowledge Explorer | browse/filter eligible objects and asserted relationships | rankings as authority, graph inference, case-specific conclusion |
| Learning overview | Candidate-to-review lifecycle and no-promotion rule | raw case ingestion, self-learning, approved Knowledge claim |
| About/governance | Program identity, principles, authorities, status, limitations | waiver of Office authority or release/publication claims |
| Future SPA Workspace | future journey, prerequisites, explicit unavailable state | functional forms, login, case data, simulated automation |
| Search results | eligible matches with type/status/source context | diagnostic answer, unreviewed result, recommendation ordering |
| Documentation exploration | governed document families and cross-references | imply documentation equals production capability |

## Cross-page Controls

Every conceptual page preserves language, audience, authority, version,
publication standing, limitations, and relationship to canonical content.
Examples are clearly examples. Future content is clearly future. Provisional or
internal content is not made public through cross-linking.

## Error and Absence Meaning

A missing, unavailable, withdrawn, or restricted representation must not be
shown as scientific absence. The conceptual experience should explain the
content status without revealing sensitive material or inventing a substitute.
