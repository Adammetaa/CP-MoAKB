# Website Capability Map

Status: Active

Version: 1.0

## Must Have

- clear Program and Website purpose, non-goals, and publication status;
- governed knowledge and documentation browsing;
- top-level Home, Knowledge, Investigation, Knowledge Explorer, Learning, About,
  and clearly future SPA Workspace destinations;
- exact source, provenance, authority, version, review status, and limitations
  for substantive eligible content;
- explainable Investigation flow and permanent layer separation;
- search over separately eligible content without diagnostic ranking;
- governed relationship navigation and stable cross-references;
- Thai-first-compatible terminology presentation and English technical alignment;
- clear Alpha/future/deferred labeling; and
- accessibility and device-independent content semantics as future design input.

## Should Have

- package and object-type browsing;
- glossary and terminology relationship exploration;
- explicit “why this is shown” and “what this does not mean” explanations;
- version and supersession history;
- source/evidence/review trace summaries;
- crop-independent examples; and
- documentation pathways for SPA and reviewer preparation.

## Could Have

- saved public exploration state without scientific personalization;
- compare eligible object versions or package relationships;
- shareable governed references;
- printable or exportable public summaries under separate output governance; and
- expanded localization and accessibility aids.

## Deferred

SPA case workspaces, authentication/role implementation, Human Review operation,
field/offline operation, case/evidence upload, Management Options, enterprise
administration, analytics, production crop content, and every AI or automatic
selection/classification/inference capability are deferred.

## Classification Rules

A capability belongs in Must Have only if Alpha cannot deliver trusted public
knowledge exploration without it. Should/Could capabilities cannot delay the
minimal Alpha. Deferred capability descriptions establish boundaries and
prerequisites, not implementation approval.
