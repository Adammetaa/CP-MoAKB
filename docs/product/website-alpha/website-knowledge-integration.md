# Website Knowledge Integration

Status: Active

Version: 1.0

## Integration Principle

Website Alpha consumes governed, versioned, separately publication-eligible
representations. It never copies content into a parallel Website knowledge base,
silently transforms scientific meaning, or treats presentation metadata as knowledge.

## Architecture Consumption

| Authority | Website use | Preserved boundary |
|---|---|---|
| Observation Architecture | explain and display eligible bounded Observation meaning, context, provenance, and uncertainty | Observation does not become Evidence, Claim, or Diagnosis |
| Observation Vocabulary | present reviewed neutral terms, definitions, language relationships, and status | label or local name does not confirm scientific identity |
| Investigation Ontology | explain states, gaps, questions, needs, candidates, differentials, findings, and review | flow does not execute or promote layers |
| Investigation Question Bank | explain eligible Question Pattern intent, scope, applicability, response expectation, and neutrality | Pattern is not instance; no selection or decision tree |
| Knowledge Objects | present exact eligible representations and relationships | Website page is not the canonical object |
| Knowledge Packages | expose eligible package scope, version, authority, contents, limitations, and lifecycle | Package presence does not imply applicability or publication of every referenced item |
| Explainability architecture | reconstruct source, evidence, knowledge, relationship, review, version, and limitation paths | path does not prove a conclusion or rank alternatives |

## Non-duplication Model

Every displayed item retains a conceptual reference to its canonical governed
object or document and exact version. Website-specific summaries are
Representations with declared purpose, language, derivation, review, and limits.
Corrections occur through owning governance, not page-local scientific edits.

## Eligibility and Visibility

Integration begins only after the relevant content has required Knowledge,
Scientific, rights, privacy, Release, and Publication eligibility. The Website
must distinguish unavailable, deprecated, superseded, withdrawn, and retired
material and must not expose case-bound or internal-only objects.

## Search Boundary

Search operates only across eligible representations and returns traceable
results. Matching, ordering, or co-occurrence creates no claim, evidence role,
scientific equivalence, case relevance, or recommendation. Search implementation
and indexing are not defined.

## Future Integration

SPA Alpha may reference the same governed objects inside role-bounded case work.
It must not fork public and operational knowledge meaning. New product/runtime
integration requires separate architecture, implementation, validation, and release approval.
