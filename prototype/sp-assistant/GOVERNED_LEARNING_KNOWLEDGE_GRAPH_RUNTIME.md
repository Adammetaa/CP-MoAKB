# Governed Learning / Unified Knowledge Graph Runtime

## Purpose and permanent boundary

Step I implements: Runtime evidence and gaps → Learning Nomination → Reviewed Case Bundle → Knowledge Assertion Candidate → explicit promotion gates → Human Domain Review → governed field-derived state → authority-preserving graph projection.

The runtime learns what deserves review; it does not teach itself truth. Observation is not Evidence, Evidence is not Knowledge, a Case or Local Pattern is not Knowledge, an Outcome is not efficacy, and a graph connection does not transfer authority. Knowledge Promotion is separate from Model Training.

## Server authority and lifecycle

SQLite owns Learning Nominations, immutable Reviewed Case Bundles, Knowledge Assertion Candidates, and every Knowledge Promotion Review. Stable request IDs make mutations idempotent. Expected promotion counts protect concurrent review. The browser is a view, cache, or draft client and reconstructs all state from the authenticated server.

The categorical maturity model is LE0 RAW_NOMINATION, LE1 STRUCTURED_LEARNING_CANDIDATE, LE2 REVIEWED_CASE_BUNDLE_READY, LE3 CANDIDATE_KNOWLEDGE_ASSERTION, and LE4 DOMAIN_REVIEWED_GOVERNED_ASSERTION.

LE4 remains FIELD_DERIVED_GOVERNED_KNOWLEDGE when its source is field-derived. It is never scientific or regulatory authority merely because a Domain Reviewer approved it.

## Learning Inbox and nominations

The closed nomination vocabulary covers Knowledge, Candidate-relationship, action-evidence, management, regulatory, sampling, visual-vocabulary, Thai-language, field-pattern, unexpected-outcome, workflow, terminology, conflict, source, source-extraction, and Working-Knowledge inputs. Sources retain the originating runtime: Field Case, Steps C/D/F1/F2/H, visual and conversation mappings, SPA/reviewer feedback, workflow telemetry, Faculty Working Knowledge, ChatGPT Research Note, or future source extraction.

A nomination retains stable identity, owner/privacy scope, optional Field/Season/Case, source type/reference, optional subject identity, original description, structured gap, proposed scope, supporting and contradicting references, limitations, privacy and rights state, status, time, context hash, version, supersession, and provenance. It explicitly records that nomination is not a Claim, changes no canonical knowledge or Candidate Provider, and is not training-eligible.

## Deterministic grouping and Knowledge Gap Register

Nominations group only by governed gap code, stable subject identity, and originating runtime. Labels and opaque embeddings are not merge authority. Counts do not increase scientific authority.

The Knowledge Gap Register exposes gap code, subject, source runtime, frequency, distinct authorized Cases and Fields, first/last seen, state, linked nominations, review state, and priority inputs. Frequency means Knowledge-work demand only; it never means prevalence, incidence, disease importance, risk, or biological truth.

The Knowledge Work Queue uses explainable categorical ordering: regulatory/safety blocks first, then repeated runtime blocks, review-ready items, and intake. Each item states that priority is neither biological risk nor prevalence.

## Reviewed Case Bundle and independence

A reviewer explicitly includes and excludes Cases. The frozen Bundle retains Case/Field/Season references, Step C, Guidance, F1, decisions, actions, Outcomes, reviewed visual material, Local Pattern references, supporting and contradicting material, gaps, alternatives, correction lineage, source revisions, privacy/rights state, reviewer attribution, limitations, a context hash, and an immutable bundle hash.

Duplicate Cases, observations, events, images, sources, actions, or Outcomes never create independent corroboration. Independence is an explicit review state. A Bundle is a reviewed snapshot and is not Knowledge.

## Entity, identity, and Assertion model

Entity nodes carry stable label-independent identity. Assertion nodes carry predicate, optional object or literal, Claim type, crop/stage/spatial/temporal scope, source authority class, evidence links, limitations, conflicts, review state, versions, and provenance. Truth is not written directly onto an Entity.

Labels never merge identity. Synonym is not identity, trade name is not active ingredient, active ingredient is not Product, Product is not Registration, Candidate is not cause, and Registration identity is not approved Crop × Target × Use.

## Source authority separation

The graph preserves CASE_EVIDENCE, FIELD_DERIVED_LOCAL_KNOWLEDGE, SCIENTIFIC_AUTHORITY, REGULATORY_AUTHORITY, REGULATORY_SUPPORTING_OFFICIAL_MATERIAL, MOA_CLASSIFICATION_AUTHORITY, MANUFACTURER_COMMERCIAL_SOURCE, HUMAN_EXPERT_INTERPRETATION, and WORKFLOW_OPERATIONAL_EVIDENCE as non-inheriting classes.

Field-derived assertions must use CASE_DERIVED or LOCAL_FIELD_EVIDENCE. Scientific, regulatory, and manufacturer classes require their own bound sources. authority_target cannot upgrade or transfer authority.

## Unified graph and conflicts

The server produces a deterministic normalized graph projection without an external graph database. It exposes nodes, edges, assertions, authority, provenance, conflicts, versions, scope, review state, and source references. Governed edges include support, contradiction, derivation, review, supersession, contextual relations, nomination, promotion, and conflict.

Conflicting Assertions coexist with a CONFLICTS_WITH relationship. Neither field material, scientific material, regulatory material, nor manufacturer material overwrites another. Graph structure alone cannot answer diagnosis, best treatment, or product winner.

## Promotion gates and Domain Review

Every attempt evaluates named categorical gates for identity, provenance, source traceability, bounded scope, Case review, independence, contradictions, alternatives, privacy, rights/consent, appropriate authority class, Domain Review, and current corrections. Results are individually explained. There is no hidden weight, score, probability, or confidence percentage.

Human Domain Review records reviewer, role, authority scope, decision, rationale, supporting and contradicting evidence, limitations, timestamp, source versions, and context hash. Approval, return, rejection, split, deferral, conflict marking, and canonical-review routing are durable dispositions.

## Canonical, runtime, regulatory, and manufacturer boundaries

CANONICAL_REVIEW_CANDIDATE creates only a review-queue state. It does not mutate Canonical Scientific Knowledge or Knowledge Explorer publication.

A reviewed assertion may become ELIGIBLE_FOR_RUNTIME_MATERIALIZATION_REVIEW, but Step I never hot-writes Candidate Provider, management rules, thresholds, visual vocabulary, ontology, or regulatory rules. Human Review cannot create Registration, approved use, Crop × Target × Use authority, scientific authority, or missing source evidence.

Repeated positive Outcomes do not validate manufacturer efficacy, rank Products, create preference, prove resistance, optimize dose, or create a Recommendation. MoA classification remains descriptive authority only.

## Step H, F2, and Step E integration

Step H can submit FIELD_PATTERN_CANDIDATE; it never self-promotes. Step I retains Local Pattern scope, independence, denominator limitations, privacy, conflict, and NOT_EVALUATED outbreak status.

Step F2 can submit UNEXPECTED_OUTCOME or action-evidence gaps. Similar Outcomes remain learning inputs, not efficacy, Product performance, resistance, dose optimization, or Recommendation optimization.

Step E recognizes bounded intents such as “เก็บเคสนี้ไว้เป็นความรู้”, “เรื่องนี้เจอบ่อย น่าจะต้องเพิ่มความรู้”, and “จำคำว่าข้าวจ๋อยไว้หน่อย”. The response is: “เก็บเป็น Learning Candidate ไว้แล้วครับ ยังไม่เปลี่ยนความรู้หลักจนกว่าจะผ่านการตรวจ”. Ambiguity produces at most one clarification. Provider output cannot approve, promote, set authority, resolve conflict, or create canonical rules.

## Future Working Knowledge and source extraction

Faculty notes, ChatGPT research notes, and source-extraction nominations remain Working or Candidate knowledge until source and review gates pass. No ChatGPT memory is ingested. The source-extraction hook can later retain a PDF source span and reviewer, but Step I contains no mass extraction, crawling, or automatic ingestion pipeline.

## Privacy, training, publication, and corrections

Records are same-authenticated-user scoped. Bundles exclude exact geometry and preserve authorized stable Field references. No cross-user aggregation or existence leak is implemented. Public/general knowledge cannot carry personal identity, farmer name, phone, address, exact location, or sensitive commercial detail.

training_eligible is false throughout. Step I creates no training dataset, fine-tuning job, embedding-based model update, or automatic model learning. Image training remains governed by existing consent and rights controls.

Step I emits PUBLICATION_NOT_ELIGIBLE; it never publishes. Publication still requires separate authority, privacy, rights/consent, editorial, release, and Project Owner approval.

When a Case, Observation, Evidence, Outcome, Local Pattern, or bound source changes, dependent Bundles, Assertion Candidates, and prior promotion projections become STALE_REVIEW_REQUIRED. Historical snapshots and decisions remain immutable.

## Timeline and authenticated APIs

The Step G Timeline may reference nomination, Bundle, Assertion Candidate, and promotion review records. Each remains a chronology reference, not Knowledge Evidence.

Authenticated endpoints expose Learning Nominations and intent interpretation, Knowledge Gaps and Work Queue, Reviewed Case Bundles, Assertion Candidates, promotion reviews/history, and Knowledge Graph/context. All reads reconstruct from server state and all ownership failures fail closed.

## Explicit non-goals

No automatic self-learning, canonical promotion, rule update, ontology/vocabulary mutation, regulatory authority creation, model training, fine-tuning, training dataset, mass PDF extraction, web crawling, external vector/graph database, causal inference, efficacy learning, Product ranking, commercial Recommendation, outbreak authority, publication, deployment, release, or UI redesign is implemented.
